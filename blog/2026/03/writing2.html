gdbm package failure → OSH tries to execute directories on $PATH

Let's Write A PATH Traverser (aolsen.ca) by Aidan Olsen

We encountered an OSH disagreement building the Alpine gdbm package, and reduced it to a bug in the $PATH lookup logic.

In this post, Aidan explains how $PATH works, including some quirks that surprised me!

We often referred to the source code of other shells — the POSIX shell spec is generally not sufficient.

  • More notes: #bug-post-mortem > gdbm failure - OSH tries to execute directories on PATH

(The article by Gabe linked in the previous post is also related.)

Implementing GLOBIGNORE

Implementing GLOBIGNORE (daveads.github.io) by Daveads

Daveads wrote notes on implementing the bash $GLOBIGNORE feature in OSH, which affects globbing results like *.py. It involves both parsing and evaluation, so it's yet another little language in shell!

I often say that it's effective when one person writes the tests, and another writes the code. Two people may "converge" on a higher quality solution than one:

  • #documentation > One person writes the tests; another person writes the code

In this case, Ellen Potter wrote comprehensive spec tests for $GLOBIGNORE two years ago, in late 2023.

I unfortunately didn't have time to implement this myself in the last 2 years, because we were busy with YSH and more. But Daveads pushed it forward, and Ellen's work ended up being essential for that!

Dev Guide: Zephyr ASDL

ASDL for Oils for UNIX Contributors, Algebraic Datatypes in Python (and C++) (aolsen.ca) by Aidan Olsen

Many years ago, I wrote several blog posts tagged #ASDL, explaining our DSL for algebraic data types.

We continue to use Zephyr ASDL, and this post is a great introduction to it. It's concise, and covers the most important usage patterns.

ASDL is also still evolving. While reviewing this post, I posted some thoughts on Zulip:

  • #zephyr-asdl > Notes on some holes in ASDL

In particular, I was reminded of an issue that Koichi Murase ran into last year:

  • #oils-dev > Importing ASDL simple sum from frontend/syntax.asdl

Those threads have detail, which I welcome you to read. The key points are:

  • Zephyr ASDL isn't an "air tight" abstraction. It's generally simple and easy to use, but it has some holes. We'll continue to improve it.
  • At first, we generated only Python code from ASDL schemas. Later, we stated generating C++ too. This adds constraints, e.g. due to the C compilation model.

Similarly, if someone does a Rust translation of Oils, there will be issues related to the target language! One issue I know about is due to the "shared types" aka "shared variants" feature that Aidan mentioned:

  • #zephyr-asdl > Tags vs. Types with Rust traits

Future Zephyr ASDL Features

What else might we add to ASDL? Generating visitor base classes would be useful for several tools: formatter, linter, dependency walker, and translator:

  • #tools-for-oils > How should we generate tree walkers?

I did some research on this design issue in December:

  • #tools-for-oils > How does Ruff walk trees?

Thanks to All Contributors

In this post and the previous one, we reviewed 12 articles by contributors. But there were many people who contributed to Oils who did not choose to publish (or haven't done so yet). I particularly want to thank:

Koichi Murase (author of ble.sh) — for a deep overhaul of the $IFS word splitting algorithm in OSH.

  • Word splitting bugs were the most common type of disagreement last year. Fixing these issues unlocked other bugs, and other contributors tackled them in parallel.
  • I mentioned the word splitting work in September: Eight Releases of Oils in 6 Months. I hope Koichi has the time to write about this work in detail!

Andriy Sultanov — for his prolific bug fixes and feature implementations, across many areas of the codebase.

  • He started with some of the trickiest bugs in OSH, moved on to mycpp (a metalanguage), and then YSH.
  • I wrote about this in December: Oils 0.37.0 - Alpine Linux, YSH, and mycpp

(Koichi also overhauled bash-compatible arrays in OSH, mentioned last May: Oils 0.27.0 - Contributors and Notable Changes)

Conclusion

Now that I re-read these posts, I'm reminded of all the excellent work from contributors! It's also hard work.

I will quietly work on the backlog of pull requests, and I hope to come back to the project with new energy later this year! I also want to work on a few server-side projects that complement Oils.
